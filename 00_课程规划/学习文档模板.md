# 每日学习文档模板

复制以下模板编写单篇课程。方括号内容是提示，交付正文时替换或删除。读者课文不展示阅读时间、阶段、前置、环境、源码基线、验证状态等管理字段；这些记录放在总目录、实验手册或交接资料。

```markdown
# DayNNN：课程标题

## 摘要

[300～600 字，概括本课解决的问题、关键结论、因果关系和正文展开顺序；摘要不替代正文必要解释。]

## 正文

[1500～2000 字；一个主要学习目标，由两至三个紧密相关的知识点支持。围绕问题缘由、背景、设计原因、机制、例子、对照和迁移自然展开；首次出现术语时就地解释。]

[适度使用 Markdown 加粗、下划线或少量红色标记突出重要术语、因果结论和易混淆边界；强调服务理解，避免整段加粗和颜色滥用。]

[可在正文中嵌入示意图、情境推理、思考及答案解释、总结和直接相关来源；不另设与摘要、正文并列的固定板块。教学抽象和虚构案例须注明。]
```

## 字段要求

- 正文 1500～2000 字；摘要建议 300～600 字并另计。一篇只有一个主要目标，篇幅须由知识增量支撑，不靠复述、代码量或纯数据凑数。
- 课文标题之后只出现 `## 摘要` 和 `## 正文` 两个一级内容板块；阅读时间、估时免责声明、阶段、前置、环境和验证状态属于管理信息，不放在课文。
- 字数口径在内部交接/检查记录说明：统计 `## 正文` 内教学文字，不含摘要、标题、元数据、导航、链接和答案；说明计量单位，不混称汉字数与英文词数。
- 源码课程记录仓库、分支/标签、文件路径及必要提交号；Linux 与 OpenHarmony 版本不得混写。可执行实验的环境、状态和验证范围记录在实验手册。
- 术语首现时解释；类比说明边界并回到技术含义；图和示例服务于当前问题。
- 重要术语、因果关系和易混淆边界适度用粗体、下划线或少量红色标记突出；不要让视觉强调替代解释。
- 阅读、实践与验收状态分别记录在学习记录，不在课文头部展示。
