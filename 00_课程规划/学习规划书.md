# OpenHarmony 内核学习规划书

## 学习对象与目标

面向具备大一程度 C/C++、能使用 Linux 基本命令并编译运行程序的学习者。课程不重复讲变量、循环等入门内容；遇到指针、结构体、函数指针、位操作、链接等内核阅读必需知识时，按需补足。操作系统按零基础设计，进程、系统调用、地址空间、调度、同步等概念首次出现时解释。

课程以 Linux 内核通用机制为学习主线，最终面向 OpenHarmony 标准系统内核集成、源码阅读、测试和贡献准备。OpenHarmony 是包含内核、系统服务、框架与应用层的开源操作系统平台；商业 HarmonyOS 是不同定位的产品体系。分布式软总线、应用框架等用户空间能力不等同于内核功能。OpenHarmony 支持 LiteOS 与 Linux 等内核路线，本课程聚焦标准系统采用的 Linux 路线，不要求先学完 LiteOS。

## 路线与能力目标

Day001～Day005 为认识项目、分层、多内核、一次操作的职责边界和贡献路径的先导课；Day006～Day030 建立内核认知并观察系统行为。之后依次学习系统调用、进程线程、调度、虚拟内存、文件与 VFS、并发同步，再进入构建调试、测试复现、OpenHarmony 集成、专题阅读及贡献实践。完整编号为 365 天，复习与验收日计入阶段，不另加天数；每七天安排一次复习或自测。

前 180 天的目标是能解释并通过基础实验观察常见机制，全年目标是形成准备小型文档、测试或缺陷补丁所需的方法与记录。目标不代表按日历完成即具备独立开发能力，也不保证补丁被合并。

## 每日学习方式

- 每篇课程只有一个主要学习目标；正文按每日文档标准为 1500～2000 字，并配 300～600 字独立摘要。阅读节奏只用于内部规划，不写入读者课文，也不以字数换算学习者的真实阅读时长。
- 课文对重要术语、因果结论和易混淆边界做适度视觉强调，可用粗体、下划线或少量红色标记；不以大面积格式强调制造信息量。
- 课文尽量使用短段落、直接指代和正面表述，避免重复背景与多余限定；每张图只服务一个教学问题，图前提出问题、图后解释含义与边界。图为辅助，不能代替原因和机制的正文说明。
- 配图可用静态关系图，或在确有教学价值时用动图；风格与工具不固定、不强制安装专用工具。保留可编辑源及署名许可，输出格式需符合当前网页构建器和分享版能力。
- 页面验收要看真实生成结果中的段落、强调、配图和窄屏显示；构建成功不等于视觉检查或学习者试学完成。
- 微练习和扩展实验若有则安排在独立学习计划或实验手册中，下载、安装、构建等待与课程阅读分开考虑。
- 课文可在正文内自然组织思考、解释与小结，不强制套用额外的“今天动手/自检/一句话总结”板块；学习记录仍区分阅读完成、实践完成、验收通过。
- 前期优先使用 Linux 用户空间观察工具与 `/proc`；后期再使用可恢复的虚拟机或 QEMU。普通 Linux 的实验结果不能替代 OpenHarmony 产品配置验证。

## 建设节奏

### 内容与阅读展示分工

Markdown 保留为课程内容唯一来源，由 Git 管理修订；HTML 阅读版由工具自动生成，不手工维护另一份课程正文。课程内容仍为标题、摘要与 1500～2000 字正文，背景、例子和强调样式保留；不向正文追加阅读时间或管理字段。

阅读版负责字体、行宽、行距、长文目录、深浅色模式和手机适配，提供首页及上下课导航。静态站点生成至 `_site/`，打开 `_site/index.html` 即可离线阅读；每课另生成 HTML/CSS/JavaScript 三合一的单文件分享版，并将必要本地图片内嵌。工具、模板、样式、课程图片源与依赖定义以及生成目录均纳入 Git，便于复审和发布；重建前核对输出差异并只同步本次生成的文件。

同一次构建另为每篇课程生成 `_site/share/课程文件名_分享.html`，将 HTML、CSS、JavaScript 及必要图片等资源内嵌为独立文件。分享版可单文件发送、离线直接打开，保留页内目录、深浅模式、重点样式和手机适配；不依赖站点首页或其他课程文件。两种展示共用 Markdown 内容源，不另行编写或维护正文。

普通阅读版与单文件分享版的本地静态生成工具已实现，依赖和构建命令见根 README。内容复审与页面验证分开进行：生成成功不代表课程内容审核通过；页面仍需在浏览器核对内容一致性、链接、重点样式、窄屏、深浅模式及离线行为；分享版需移至独立目录验证不依赖站点资源。未执行的人工检查不能记作已验证。

### 分批推进

按本规划书与课程总目录分批建设，不一次性生成 365 篇正文。Day001～Day005 已有首稿并进入深化修订；新版需重新接受内容复审和学习者试学，不能沿用旧审核结论。随后按授权建设基础课，以前 7～14 天反馈检验前置、解释充分性和实践负担，再逐步扩展。正式源码课程须注明仓库、分支或标签、文件路径与适用版本；未经核验的环境和版本明确标为待定。
