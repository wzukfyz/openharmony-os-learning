# 环境与版本基线

本文记录方案和待核验清单，不表示环境已经安装、实验已经运行或版本已经锁定。当前文档工作环境是 Windows；学习者的 Linux 环境、硬件、虚拟化能力和网络条件尚未确认。

## 分层方案

| 层次 | 用途 | 当前方案 | 确认与锁定时机 |
|---|---|---|---|
| 用户空间观察 | 前期观察进程、文件访问及系统信息 | 优先使用已有 Linux 主机、虚拟机或经确认可用的 WSL；可选择 `/proc`、`strace` 等，不要求先构建内核 | 编写 Day018 等观察课及实验步骤前确认发行版、内核、工具版本和权限；若使用 WSL，检查跟踪能力限制 |
| 通用 Linux 内核实验 | 后续在可恢复环境中构建、启动、调试与测试 | 候选为 Linux 官方维护的稳定 LTS 源码，优先 QEMU 虚拟机；版本待按课程内容、工具链及主机能力选定 | 最迟在首次构建实验前核实目标版本生命周期、架构、编译器、依赖、磁盘/内存及 QEMU 兼容性；记录标签/提交号 |
| OpenHarmony 目标验证 | 学习标准系统 Linux 内核集成与配置 | 以所选 OpenHarmony 发布分支、产品配置、内核基线、补丁集和工具链共同确定，不预设单一开发板 | Day271 集成学习前由目标任务确定分支/标签、产品、仓库提交、构建主机和验证设备；每次复现记录提交号 |

## 待核验事项

| 待定项 | 影响 | 确认方法 | 最迟阶段 |
|---|---|---|---|
| 学习者可用 Linux 环境及是否有管理员权限 | 决定 `/proc`、跟踪工具和系统配置实验能否执行 | 询问学习者并记录发行版、版本、内核版本、权限 | 用户空间观察实验编写前 |
| WSL/虚拟化支持与主机资源 | 决定使用 WSL、虚拟机或远程 Linux 主机 | 检查主机虚拟化功能、可用磁盘/内存及嵌套虚拟化限制 | 首次虚拟机实验前 |
| `strace` 等工具可用性和权限 | 决定观察命令与预期输出 | 对指定环境查阅发行版文档并实际运行最小验证 | 编写对应实验步骤前 |
| Linux 实验基线及交叉编译工具链 | 影响源码、配置、补丁和命令是否一致 | 查阅 Linux 官方发布与构建说明；针对选定提交验证工具要求 | 首次内核构建前 |
| OpenHarmony 目标分支、产品和内核 LTS | 影响源码路径、补丁、配置及构建方法 | 查阅目标发布分支的官方文档与源码仓库，记录提交号；避免从 master 推断旧版本 | OpenHarmony 集成阶段开始前 |
| 可用设备或 QEMU 产品支持范围 | 决定可进行的启动/产品级验证 | 查目标版本设备清单、镜像和模拟器支持；区分文档声称与实际运行 | 目标构建验证前 |

## 验证边界与记录格式

普通 Linux 用户空间观察只证明该 Linux 环境中的观察结果；通用 Linux 内核实验不能证明 OpenHarmony 产品配置正确。OpenHarmony 构建成功也不自动证明真实设备、所有硬件或发布产品均已验证。实验记录应注明环境、版本/提交、操作、预期、实际结果、验证范围及未测内容。没有执行则标为“待验证”，不写成已验证。
