# 阶段验收标准

验收以“能解释、能预测、能运行、能复现、能验证”为证据。学习记录分别填写阅读完成、实践完成、验收通过；阅读过文档不代表实验通过。每阶段根据实际选题调整细节，不以背术语或一次分数作为唯一依据。

| 阶段 | 能力证据与检查方式 | 实践证据 | 未通过后的补学方向 |
|---|---|---|---|
| Day001–005 先导认知 | 不看资料说明 OpenHarmony 平台、内核、用户空间组件和本课程目标的关系；在简图中定位内核 | 用本地文本读取场景区分上层展示与内核资源管理 | 重读系统分层、项目与商业产品边界；按职责重新标注场景 |
| Day006–030 内核认知观察 | 区分程序/进程、Shell/内核、用户态/内核态；预测文件读取涉及的角色与资源 | 至少完成一项已核验 Linux 用户空间观察，记录环境和实际现象；如课次只读则标实践未完成 | 回到进程、权限边界、系统调用与文件入口概念；重做观察并分开记录事实和推断 |
| Day031–060 系统调用 | 口头描述用户请求越过受控边界并返回的基本过程；不把高层 API 和单个系统调用简单等同 | 跟踪一次经核验环境中的请求，给出工具输出和解释 | 复习 ABI（应用二进制接口）和用户/内核边界；缩小跟踪问题，重做最小观察 |
| Day061–120 进程线程与调度 | 根据场景解释任务创建、共享资源、运行、阻塞与唤醒 | 运行安全的观察实验或解释提供的真实记录，环境版本清楚 | 先补进程/线程和状态概念，再学习调度；不要跳到算法细节 |
| Day121–180 内存与文件 | 画出进程地址空间与文件访问的概念关系；解释缺页、映射、VFS 的基本作用 | 结合 Linux 观察或实验解释输入、结果和边界 | 回到地址、映射及路径/文件描述符概念；将大问题拆成单一检查点 |
| Day181–210 并发同步 | 用交错执行例子指出竞态，并说明同步机制要保护的共享状态 | 使用可重复的小实验或测试验证修复前后行为 | 重新构造最小竞态，检查共享数据、临界区与生命周期 |
| Day211–240 构建启动调试 | 说明构建输入、产物、启动环境及调试信息之间关系 | 在可恢复环境完成一次有记录的构建/启动/排错检查点 | 核对版本、配置和工具链；按错误阶段分别定位，不在不可恢复设备上试错 |
| Day241–270 测试复现 | 写出环境、前置、步骤、预期、实际和判定标准，其他人可按记录复现 | 留下日志/输出与失败或成功判据；记录复测结果 | 删除非必要步骤，澄清预期并固定环境和输入 |
| Day271–300 OpenHarmony 集成 | 区分 Linux 上游基线、OpenHarmony 公共内核、产品配置与平台补丁 | 依据目标分支记录源码提交、配置、补丁与验证范围 | 重新核对目标产品文档和仓库版本；不使用其他版本的命令拼接 |
| Day301–330 专题阅读 | 将问题、源码路径、测试和提交依据关联起来 | 留存阅读笔记及可复查引用（仓库、标签/提交、文件路径） | 缩小专题范围；先找到测试入口和调用关系，再深入实现 |
| Day331–365 贡献准备与复盘 | 形成问题陈述、修改依据、验证记录和对评审意见的回应；Day361–365 汇总全年证据 | 形成小型文档、测试或缺陷贡献候选；真实提交按目标仓库现行规则进行 | 退回复现、依据和测试缺口补齐；未合并不等于未学会，记录下一步 |

## 通用验收记录

每项记录：课程/阶段、日期、环境与版本、阅读完成（是/否）、实践完成（是/否/不适用）、验收通过（是/否）、证据链接或路径、未通过原因、补学动作。阶段复习按“能否解释并给出证据”判定，不设固定分数门槛。
